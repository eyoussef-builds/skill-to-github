# الخصوصية ومعالجة البيانات

[English](privacy.md) · [الدليل الرئيسي](../README.ar.md)

## ماذا يحتوي المستودع؟

تعليمات إصدار قابلة لإعادة الاستخدام، ومراجع وقوالب فارغة، وبرنامج مراجعة للقراءة فقط، واختبارات مصطنعة، وأدلة وصور عامة. بيانات التواصل المعتمدة فقط هي `eyoussef-builds` و`hello@eyoussef.me` و`eyoussef.me`.

لا يشمل الملفات الشخصية أو المحادثات الأصلية أو تقارير العمل الفعلية أو المشاريع الخاصة أو ملاحظات الإصدار أو مسارات الأجهزة أو معرّفات الحسابات أو بيانات الدخول. مسارات مثل `~/.agents/skills/` تشرح التثبيت لحسابك أنت وليست تفاصيل جهاز المؤلف. تبني الاختبارات أمثلة مفاتيح ومسارات وبريد مصطنعة عمدًا، دون بيانات دخول صالحة أو سجلات أشخاص حقيقية.

## عند استخدام المهارة

يقرأ مساعدك المهارة التي تريد نشرها ومواردها المطلوبة. قد يرى سياق تطوير خاصًا أثناء تجهيز نسخة عامة نظيفة. ملف تعليمات Markdown لا يمنح صلاحيات حسابات ولا ينشئ حاجز أمان منفصلًا؛ تسري صلاحيات الأدوات وإعدادات النموذج والخدمات.

المسموح إرساله إلى GitHub هو الملفات العامة التي اخترتها وراجعتها ووافقت على نشرها. احتفظ بقوائم المراجعة وربط المصادر وتفضيلاتك وملاحظات حالة الإصدار خارج الحزمة العامة. ملف `references/local-profile.md` اختياري وخاص بنسختك وتتجاهله قواعد Git هنا؛ احفظه عند التحديث. قواعد التجاهل لا تحذف ما تم حفظه في السجل ولا تحمي ما تضيفه بالقوة.

تستقبل خدمة الصور الوصف والمراجع التي تزوّدها بها. استخدم مدخلات عامة أو وافقت صراحة على استخدامها، دون محادثات خاصة أو لوحات داخلية أو بيانات عملاء. تُراجع نصوص السوشيال وفق حقائق المستودع العام والملاحظات التي أعطيتها للإعلان. تجهيز النص لا ينشره ولا يرسل ردودًا ولا يفعّل أتمتة التعليقات.

يعالج النموذج والخدمات المتصلة ما تستقبله وفق سياساتها. كون البرنامج المحلي لا يرفع الملفات لا يعني أن طريقة عمل الذكاء الاصطناعي كلها تعمل دون اتصال.

## ماذا يفعل البرنامج الاختياري؟

يقرأ `review_package.py` مجلد تجهيز تختاره وقائمة JSON صريحة بالملفات. يعرض نقاط مراجعة للملفات غير المتوقعة أو الناقصة، والأسماء الحساسة، وأنماط شائعة للمفاتيح والمسارات، والبريد غير المعتمد، وكلمات خاصة حددتها، وبيانات PNG النصية وEXIF. يطبع نوع الملاحظة ومكانها النسبي دون القيم السرية المطابقة، ويحسب SHA-256. لا يغيّر الملفات ولا يرسل طلبات شبكة ولا ينشر شيئًا.

لا يستطيع الحكم على كل معلومة شخصية أو محتوى الصور أو كل ملف ثنائي أو سجل Git أو حق النشر. يجب أن يراجع المساعد المعنى والصور والملفات والسجل الكامل المتاح، ثم يقرأ ما نُشر فعلًا من GitHub. نجاح الاختبارات أو عدم اكتشاف أنماط لا يعني ضمان الخصوصية بالكامل.

## قبل نشر مهارتك

1. اقرأ كل ملف وافحص كل صورة. استخدم قوالب فارغة أو أمثلة مخترعة بدل العمل الخاص الحقيقي.
2. استبعد بيانات الدخول والمحادثات الخام والملفات الشخصية وملفات `.env` والروابط الداخلية وبيانات الأشخاص والعملاء وتفاصيل الجهاز.
3. افحص هوية كاتب ومنفّذ الالتزام، والروابط البعيدة، والسجل الكامل المتاح. يناسب التصدير النظيف بسجل جديد حزمة مستقلة جديدة، مع احترام الحقوق وقواعد المستودع الموجود.
4. راجع حالة GitHub الفعلية بعد النشر: بايتات الملفات والسجل والبيانات الوصفية والصور وأرشيفات الإصدارات.
5. استخدم أمثلة مصطنعة في البلاغات، واحتفظ بقوائم المراجعة والأدلة الحقيقية خاصة.

## الإبلاغ عن مشكلة خصوصية

راسل [hello@eyoussef.me](mailto:hello@eyoussef.me) بالملف العام المتأثر ووصف مختصر. لا تضع مفتاحًا سريًا في بلاغ عام. أي بيانات دخول صالحة تسربت تحتاج إلغاءً أو تغييرًا لدى المزوّد؛ حذف الملف الحالي لا يبطل المفتاح ولا يمحو النسخ السابقة.
