# Two public skill explainers

Produce one English and one Arabic image-generated infographic for each released skill. These are capability/starting guides, separate from any images the skill itself generates during use.

## Content manifest

Prepare a short verified manifest from the public skill and approved README:

- Skill name, audience and one concrete benefit.
- A small sequence showing the real user journey and outputs, including material approval points.
- A prominent “How to start” / “كيف تبدأ؟” panel: install from the repository, an exact short invocation/request, and the next expected action/result.
- The exact visible GitHub repository URL and only approved public attribution.
- A short prerequisite/coverage qualification if necessary to interpret the capability honestly.

Keep content short enough for a phone. Use generic illustrations and synthetic UI cards, not private screenshots, transcripts, customer data, device names, real daily metrics or hidden accounts. Do not invent success rates, savings, earnings, tested-agent counts or usage statistics. Do not list unfinished development tasks or blockers in promotional artwork; describe current supported capabilities accurately and retain material caveats in the guides.

## Visual direction

Read [the brand style](brand-style.md). Default to a readable portrait composition around 4:5, warm cream `#FAF8F2`, ink `#15130F` typography and bright yellow `#FFE04A` accents, with white/pale yellow/warm neutral panels. Carry these colors through illustrations and CTA elements; the earlier navy/purple/pastel examples are superseded. Use a few informative dimensional illustrations: a person collaborating with an AI assistant, a document becoming an output, or chats becoming a report. Large labels, whitespace and a visible GitHub CTA matter more than decoration.

Follow the user's approved brand direction when it differs. For matching languages, generate the first version, inspect it, then localize it using the image tool's supported edit/reference mechanism. Preserve the same facts and composition while adapting panel order and spacing to Arabic RTL. Keep Western numerals, commands, identifiers and URLs correct. Avoid untested QR codes, fake platform screenshots and tiny disclaimer text.

## Verification and delivery

Read both images at their normal displayed size. Check the complete URL character by character, skill name, invocation, step order, Arabic shaping, technical names, counts and qualifiers. Correct wrong facts or unreadable text through targeted image edits. A successful tool call is not content approval.

Inspect metadata for private paths, author/device details or other unintended text. Do not remove required provenance to disguise generation. Save final images as separate durable files, normally `docs/images/infographic-en.png` and `infographic-ar.png`, and link them from the README or a bilingual sharing guide. Keep originals, and record the public production briefs separately from private tool paths. Provide copyable bilingual captions with clickable GitHub links; URLs drawn into an image are not clickable.

For a multi-skill batch, preserve every requested image and offer a ZIP with the images and captions. Inspect its entries and contents before sharing. Generated work meant for a repository must not remain only in the image tool's default output directory.
